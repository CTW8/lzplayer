# console-ui-v2 实施计划

> 设计文档: ../../docs/console-ui-v2-design.md
> 创建日期: 2026-08-14

## 方案摘要

把测试台主界面从「播放器 + 一堆入口」改成「仪表台 + 播放窗」。核心是在竖屏 1080p 素材上下的黑边处
放一条**常驻两行八格仪表带**，让主屏无需打开面板即可回答"现在健康吗"；同时把控件按性质压成三层
（圆钮主操作 / 描边面板入口 / 纯文字次要控件），播放键缩成 26px 内嵌进度行以腾出高度。
额外补上仪表带与诊断面板之间缺失的连接：**每个仪表格可点，一次点击直达解释它的那一页**。
横屏沉浸时控件隐去但 chip 与性能 HUD 常驻。纯 UI 层改动，不碰 native，数据源全部复用 perf-metrics 已落地的字段。

## 关键约束（实施中不得违反）

1. **控件按性质分三层，每层只用一种视觉语言**：① 圆钮 = 唯一主操作；② 描边框 = 四个面板入口，样式完全一致；
   ③ 纯文字无框 = 次要控件。同层内不许出现样式例外（不许某个入口特别宽/特别亮/带副标题）。
   上一版的问题不在按钮数量，在把主操作/参数/开关/破坏性动作四种性质混排。
2. **优先级靠顺序和位置，不靠颜色和尺寸**。「性能」排第一即表达优先级，样式与其余三个相同；
   「停止」靠右 + 危险色**字色**，不做色块不加边框。禁止为表达优先级新增样式种类。
3. **要密度不要大按钮**。主屏价值在读数不在 chrome；全宽播放键是消费级思路，一律不用。
4. **读数旁必须有素材规格**：chip 写全 `解码路径 · codec · 分辨率帧率`。
   同一份代码在 640×360 与 1080p 上瓶颈排序完全不同，没有规格的数字不可比。
5. **三态显示**（继承 perf-metrics 关键约束 10）：`null` → `--`，负数原样显示并标红，正常值正常显示。
   禁止 `optDouble(key, -1.0)` 这类默认值把 `null` 兜掉。
6. **丢帧格只显示 `dropLate`**，不显示四类之和 —— overflow/stale/seekCatchup 语义不同不能相加。
7. **不另开定时器**：仪表带刷新搭既有 500ms 进度 tick，且只更新变化项不重建 View，
   避免测试台自身干扰 CPU 读数。
8. **灰度可读**：HW/SW 用字样、状态用颜色 + 数值双编码。
9. **本 feature 不碰 native**，只消费已有 JSON 字段；未落地的指标显示 `--`，不为它去改采集层。

## 实施步骤

0. **步骤0 前置：提交工作区已验证改动**（半天以内）
   - 当前 `ConsoleActivity.kt` / `DiagnosticsSheet.kt` 处于 modified 状态，内容是 perf-metrics 步骤5 剩余项 1、2：
     性能面板全屏拖动（`isFitToContents=false` + `expandedOffset=0`）、清除每 tick 写 perf 文件的临时脚手架。
   - 该脚手架的 `writeText` 先截断再写，调试 stop→play 时已读到空文件并误导过一次，必须清掉。
   - **验收**：两处改动作为独立 commit 落地（需用户明确同意后再执行 commit）；
     `git status` 中这两个文件干净，本 feature 的重构 diff 不与其混在一起。
   - 同步更新 perf-metrics status：其步骤5 剩余项 1、2 转 Done。

1. **步骤1 布局重构：三层控件区 + 进度行内嵌播放键**（1~2 天）
   - 重写 `activity_console.xml`：源栏 / 画面区 / 仪表带容器（占位）/ 进度行（26px 圆钮内嵌）/
     四等宽描边面板入口 / 纯文字次要控件行，自上而下六块。
   - 删掉全宽播放按钮行与六档速率分段控件（速率改为 `速率 ▾` 弹出）。
   - 面板入口高度砍到约原来一半，四等宽同样式，顺序 性能/轨道/字幕/跳转。
   - `停止` 靠右、危险色字色、无边框。
   - **验收**：竖屏下三层视觉语言各自唯一，同层内无样式例外；播放/暂停/停止/循环/速率/四个入口
     全部功能不回退；进度条与时间码不抖动。

2. **步骤2 常驻仪表带（本次核心）**（1~2 天）
   - 两行八格：主行 帧率 / 丢帧(迟到) / A/V / CPU；次行 启播 / 同步余量 / 队列音视 / 缓冲。
   - 数据源复用 `getStatsJson`（帧率/dropLate/avOffset/队列/缓冲）、启播 trace（启播总耗时）、
     稳态直方图（同步余量）、资源采样（CPU）。
   - 颜色 + 数值双编码；三态显示；丢帧只取 `dropLate`；刷新搭 500ms tick 且只改变化项。
   - 画面区 chip 补上分辨率与帧率，形如 `SW · h264 · 1080p30`。
   - **验收**：起播后八格全部有真实读数（未落地指标显示 `--` 而非 0 或 -1）；
     制造一次 seek，丢帧格**不因 `dropSeekCatchup` 变动**；灰度截图下八格可判读；
     刷新期间无 View 重建（可用 Layout Inspector 或日志确认）。

3. **步骤3 源栏折叠 / 展开**（0.5 天）
   - 打开片源后收成一行：文件名或 URL 摘要 + 规格 + 「换源」；点击展开回完整输入区。
   - **验收**：本地选择与 URL 输入两条路径在折叠/展开状态下均可用；
     折叠省下的高度确实分配给了仪表带（截图对比高度）。

4. **步骤4 仪表格子点击跳转到指定分页**（0.5~1 天）
   - 给 `DiagnosticsSheet` 增加"打开时定位到某页"的入口参数（当前 `currentTab` 硬编码 `"概览"`）。
   - 映射：帧率 / 丢帧(迟到) → 稳态页（丢帧构成 + 上屏间隔）；A/V · 同步余量 → 稳态页（分位数表）；
     CPU → 资源页（线程分布）；启播 → 启播页（瀑布图）；队列 · 缓冲 → 稳态页（队列水位）。
   - 本期只做到"落在正确分页"，**自动滚到对应行并高亮列为后续增强**。
   - **验收**：八格逐个点击，面板打开时停在映射表指定的分页，无一例落回概览页；
     "发现异常 → 定位细节"确为一次点击。

5. **步骤5 横屏沉浸态调整**（0.5 天）
   - 控件 3s 无操作自动隐藏保持不变；**chip 与左下性能 HUD 改为常驻，不随控件隐藏**。
   - 字幕避让逻辑按新控件高度校准。
   - **验收**：横屏静置 3s，控件隐去而 chip + HUD 仍在且读数继续刷新；
     旋转前后播放不中断、状态不丢。

6. **步骤6 真机截图核对与报告**（0.5~1 天）
   - 用标准素材 `/sdcard/Movies/VID_20230814_205835.mp4`（1920×1080 h264 30fps）。
   - 逐项核对：竖屏主屏、横屏沉浸（3s 前后各一张）、灰度可读性、八格跳转映射表。
   - 报告落 `test-reports/`。
   - **验收**：设计文档第 8 节七条验收标准逐条有结论；发现的 native 缺陷单独归入对应 feature 不混改。

## 依赖与顺序

- 步骤0 是所有后续步骤的硬前置（不先提交，重构 diff 与旧改动混在一起会导致归因困难）。
- 步骤1 是步骤2、3、5 的前置（容器与层级先定）。
- 步骤4 依赖步骤2（要先有可点的格子）。
- 步骤6 依赖前五步全部完成。
- 数据源依赖 perf-metrics 步骤1/2/9a（已 Done），**不依赖** 9b~9e。

## 风险

1. **文件冲突面大**：`ConsoleActivity.kt` / `DiagnosticsSheet.kt` / `activity_console.xml` 同时被
   **test-console-ui 步骤8（未收口）** 与 **perf-metrics 步骤5 剩余项** 触碰。
   - test-console-ui 步骤8 的 A 屏 / D 屏核对标准将因本次重构作废，需按新布局重写核对项 ——
     已在其 status.md 标注；建议其步骤8 与本 feature 步骤6 合并成一轮真机工作。
   - 对 `DiagnosticsSheet.kt` 只做"新增入口参数"的最小改动，不动分页内部实现，给 perf-metrics 步骤3 留位置。
2. **未落地指标的占位**：perf-metrics 9b~9e 未完成，相关格子只能显示 `--`。
   不得为了"好看"填 0 —— 零值同时可以表示"没发生"和"没在数"，是本轮踩过五次的坑。
3. **仪表带占高挤压画面区**：小屏或 4:3 素材下需确认画面区仍可判读。
4. **刷新开销**：八格 + chip 每 500ms 刷新，若重建 View 会把 CPU 读数带偏，等于测试台污染自己的测量。
5. **速率控件从分段改为弹出**：交互路径变长一步，需确认六档仍可快速切换且 HUD 速率读数同步。
