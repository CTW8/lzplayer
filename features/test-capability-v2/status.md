- [x] **步骤6: A/V 同步外部地面真值** (2026-08-28, commit `434381c` 能力 + `d688f9b` 精度改进)
  - **项目第一条不依赖播放器内部状态的同步判据**。此前 `syncWorstMs` 取自
    `VEAVsync::getLastDiffUs()` = 视频 pts − 媒体时钟，**两个内部量相减** ——
    时钟本身偏了它也会自洽地显示"同步良好"，从未被任何外部来源验证过。
  - 做法：素材每帧顶部 **8 个黑白色块二进制编码帧号**，截屏解色带即得屏幕上真实显示的帧号。
    **色带比 drawtext 烧录数字更可靠**（只判像素亮暗，不受字体渲染与压缩伪影影响），
    并绕开本机 ffmpeg 缺 libfreetype 的限制 —— 这正是 net-playback-harness 步骤7
    当时记为"未做"的那一项。
  - **精度四处改进（`d688f9b`）**：① 墙钟由固定 1.5s 估算改为**截屏前后时刻中点实测**
    （screencap 耗数百毫秒使分母偏小，比值系统性偏高）；② **中间灰度视为解码失败并剔除**
    （一次算出 +7017ms 漂移正是这类失败被当成有效帧号）；③ 采样点取 3×3 邻域均值；
    ④ **容差按分辨率推导且两项独立误差按平方和合成**（直接相加会撑到 11%，几乎测不出问题）。
  - 结果：比值 **1.25 → 1.014~1.034**（那 25% 偏差全是测量误差，不是播放器问题）；
    帧号单调递增全 PASS；累计漂移 −41 ~ +13 ms，**均小于半帧（40ms）**。
  - **两条素材约束（实测踩出来的，已写进脚本头部）**：总帧数 < 256（色带 8 位，绕回与解错
    在稀疏采样下无法区分）；起播 6s + 采样 N×1.5s ≤ 素材时长（否则末几次采样落在片尾之后，
    帧号停住被误判为"画面停滞"）。
