## 方案摘要

net-playback-harness 收口后，2026-08-22 ~ 08-28 之间又产出了一整套测试能力，
把 `features/status.md` 文末「候选需求」里的 6 项一次性做完，但**当时没有任何一项在
features/ 登记**（features/ 最后一次更新停在 2026-08-22 的 `89dd5b7`）。
本 feature 是对这批工作的**合并补登记**：七项能力各为一步，全部已完成并有提交与归档基线；
方案与原则不重写，统一指向 `docs/test-system.html`。

**这批能力的共同定位**：此前的测试全是「单动作 → 等稳定 → 看数字」，
结构上抓不到时序类、错误路径类、生命周期类问题；本期补的正是**触发手段**（故障注入、
时序压力、生命周期事件）与**外部判据**（A/V 地面真值、跨轮次对照），
而不是又一批指标。

## 实施步骤

1. **故障注入**（`-PveFaultInject=true` 编译期隔离）：三个注入点
   `failHwCreate` / `failHwConfigure` / `failHwAfterFrames`，JNI 静态通道 + intent 参数。
   验收：默认构建 apk 内 `VEFAULT inject` 字符串 **0 处**；三条路径真机各触发一次，
   运行期 fallback 播放不中断。
2. **状态机遍历**：从每个状态发每个命令，实测留痕与 `VEPlayerDriver` 守卫白名单**双向**比对。
   验收：11 格覆盖 ≥10 格，未覆盖格必须给出原因。
3. **时序压力**：seek 风暴 / 命令抖动 / CPU 负载注入三场景，判据为**留痕自洽**而非"跑完不崩"。
   验收：三场景通过，且**压力自检**（活动量 ≥5）证明压力真的施加了。
4. **生命周期矩阵**：background / lock / rotate / switch-src / open-release 五场景。
   验收：五场景 PASS，压力自检信号**按进程过滤**后仍成立。
5. **格式矩阵**：音频轴（采样率 5 档 / 声道 2 档 / 编码 3 种）+ 容器轴（mp4/mkv/ts）共 11 组合。
   验收：每个素材 VESTAT ≥3 秒且无 ERROR；素材脚本可复现生成、不入库。
6. **A/V 同步外部地面真值**：每帧顶部 8 色带二进制编码帧号，截屏解码得屏幕真实帧号。
   验收：帧号单调递增；推进比值落在**按分辨率推导**的容差内。
7. **`docs/test-system.html`**：系统架构文档，与 `test-capability-guide.md` 分工
   （前者"为什么这么组织"，后者"该敲什么命令"）并互加引用。

**附带交付（不单列步骤）**：跨轮次对照工具 `scripts/compare-reports.py`
—— 指纹不一致即拒绝比较、九列数值按列定阈值、判据变化单独列出，覆盖候选需求第 5 项。

## 关键约束

1. **注入能力必须编译期隔离**，不得做成运行时开关：能在生产包里打开的故障注入
   本身就是稳定性风险。判据是"默认构建里字符串 0 处"，不是"默认关闭"。
2. **注入类参数必须有"注入已生效"的独立回读**：`VEFAULT inject` 留痕 + 服务端日志。
   "注入没生效"与"注入生效但无影响"在被测端长得一模一样。
3. **每个压力/矩阵类用例必须自带压力自检**：没施加压力的 PASS 是假 PASS，
   且自检信号必须**按本进程过滤**（否则会测到系统其它媒体组件的活动）。
4. 素材不入库，脚本可复现生成；每份结果归档到 `test-reports/<用例>-<日期>/`。
